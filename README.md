# zh-copy-lint

检查中文文稿里那些「一眼看不出来、发出去才会被挑出来」的排版问题。

写中文科技稿的时候，稿子里最容易留下的不是错别字，而是中英文之间多了一个空格、句号用了半角、省略号打了三个点。`zh-copy-lint` 把这些规则写成脚本，跑一遍就能定位到具体的行和列。

```console
$ zh-copy-lint draft.md
draft.md:3:9: C001 中文与英文/数字之间不应有空格
draft.md:3:15: C003 中文句子里应使用全角标点：, -> ，
draft.md:3:22: C008 数字与单位之间不留空格
draft.md:3:24: C004 省略号应写成……

共 4 处问题
```

## 安装

需要 Python 3.9 及以上，无第三方依赖。

```bash
pip install git+https://github.com/shenwuyue0202/zh-copy-lint.git
```

也可以直接克隆下来用：

```bash
git clone https://github.com/shenwuyue0202/zh-copy-lint.git
cd zh-copy-lint
python -m zh_copy_lint README.md
```

## 用法

```bash
zh-copy-lint draft.md            # 检查单个文件
zh-copy-lint docs/               # 递归检查目录下的 .md / .txt
zh-copy-lint --fix draft.md      # 自动修复可修复的问题
zh-copy-lint --format json .     # 输出 JSON，方便接进编辑器或 CI
zh-copy-lint --ignore C009 .     # 忽略某条规则，可重复使用
zh-copy-lint --cjk-space none .  # 顺带要求删掉中英文之间的空格
zh-copy-lint --list-rules        # 列出全部规则
```

退出码：`0` 没有发现问题，`1` 发现问题，`2` 没有找到可检查的文件。直接接进 CI 就能拦住带排版问题的稿子。

## 规则

| 规则 | 说明 | 默认开启 | 可自动修复 |
| --- | --- | --- | --- |
| C001 | 中文与英文/数字之间不应有空格 | 否，需 `--cjk-space none` | 是 |
| C002 | 中文字符之间不应有空格 | 是 | 是 |
| C003 | 中文句子里应使用全角标点 | 是 | 是 |
| C004 | 省略号应写成…… | 是 | 是 |
| C005 | 破折号应写成—— | 是 | 是 |
| C006 | 重复标点只保留一个 | 是 | 是 |
| C007 | 含中文的括号应使用全角（） | 是 | 是 |
| C008 | 数字与单位之间不留空格 | 是 | 是 |
| C009 | 段末缺少句末标点 | 是 | 否 |
| C010 | 顿号连续使用，检查是否漏字 | 是 | 否 |

C009 和 C010 只提示不自动改，因为改标点等于改意思，交给人判断更稳妥。标题、引用和列表项允许不以句号结尾。

C001 默认不开。中文与英文之间加一个空格是不少出版物采用的规范，这属于各家的风格选择，不该由工具替你决定；内部规范要求紧排的话，加上 `--cjk-space none` 就会连带把空格一起清掉。

## 设计上的几个取舍

**跳过代码和链接。** 反引号里的内容、围栏代码块、`http(s)` 链接都不参与检查，否则 `` `npm run build` `` 这种写法会被误报成中文里的空格。

**不碰数字里的点。** `3.5mm`、`1,000` 里的分隔符不算半角标点，只有中文句子里孤立的 `,` `.` 才会被报出来。

**修复可重复执行。** `--fix` 对同一份文稿跑两遍结果一致，不会越改越乱；反引号里的内容原样拼回去。

**只做排版，不做文风。** 这不是文案助手，不判断句子好坏，也不压缩长句。它只回答一个问题：这段文字的标点和空格，是不是符合中文出版习惯。

## 已知限制

- 按行处理，跨行的句子（比如手动换行的段落）会分别判断，C009 可能误报。
- 只认中文和拉丁字母数字，不含日文假名、韩文的同类规则。
- 全角括号规则只处理圆括号，方括号和引号暂未覆盖。

## 开发

```bash
python -m unittest discover -s tests -v
```

规则写在 `zh_copy_lint/rules.py`，每条规则返回 `(规则号, 列号, 说明, 是否可修复)`，修复逻辑集中在 `fix_line`，测试在 `tests/test_rules.py`。
